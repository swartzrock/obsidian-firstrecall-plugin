Summary

CueCraft should explore a richer visual study layer where the left margin, cue supports, section state, and final summary become graphical memory scaffolding rather than static text blocks. The proposal keeps the current non-destructive Obsidian layer and selectable HTML text invariant, while testing five expressive surfaces that could become presets or future modes.

Problem Frame

The current product promise is a retention loop: see a question, try to recall, reveal the source, then check the big picture against a summary. The existing UI already supports this with CodeMirror cue widgets and a Cornell view, but the generated question, keywords, and summary still read mostly like adjacent text. The opportunity is to make the generated structure spatial, graphical, and emotionally memorable without modifying the Markdown file.

Requirements

R1.

Margin Slide Reel

Render each section's question as a vivid miniature slide in the left margin. The note remains the reading surface, while the margin becomes a navigable deck of active-recall prompts.

  • Retention move: spatial anchors make each section easier to revisit from memory.
  • Question treatment: big, title-card wording with one section question per slide.
  • Keyword treatment: three tiny support chips or bars on each slide, not a full tag pile.
  • Summary treatment: the final slide becomes the study takeaway checkpoint.

R2.

Concept Constellation

Transform keywords into a visible semantic map around the question, then connect those maps into a note-level constellation. The learner sees how terms relate before trying to explain them.

  • Retention move: visual association turns isolated keywords into a mental retrieval path.
  • Question treatment: the question is the central node for each section.
  • Keyword treatment: keywords become orbiting nodes grouped by role or meaning.
  • Summary treatment: summary is the bridge sentence that names the pattern across clusters.
keyword graphsection memory map

Best fit: concept-heavy notes where keywords should show relationships, not merely hint terms.

R3.

Recall Radar

Show a section-by-section review heatmap that combines cue confidence, freshness, reveal history, and summary coverage. The learner gets a scanable map of what to study first.

  • Retention move: attention is guided toward weak, stale, or unrevealed sections.
  • Question treatment: questions remain visible, but the margin ranks their study urgency.
  • Keyword treatment: keyword supports are dimmed until the learner asks for a hint.
  • Summary treatment: summary coverage shows whether the final takeaway reflects all major sections.

R4.

Manga Review Rail

Render the study path as a four-panel visual story: setup, tension, reveal, payoff. The left rail becomes a playful sequence that makes the section's answer feel like a narrative beat.

  • Retention move: narrative order helps learners reconstruct the answer from story beats.
  • Question treatment: each panel converts the question into a staged prompt.
  • Keyword treatment: keywords become props in the panel, not chips below it.
  • Summary treatment: final panel compresses the section into one "payoff" sentence.

R5.

Short-Form Hook Mode

Offer an optional high-energy review mode where each question is rewritten visually like a short-form title card. This is not the default reading surface; it is a deliberate sprint mode for recall reps.

  • Retention move: memorable phrasing increases the chance a learner will try the question again.
  • Question treatment: the active-recall question becomes a bold hook while retaining its answer intent.
  • Keyword treatment: supports are sequenced as tappable or revealable beats.
  • Summary treatment: the note takeaway becomes the final title card.

Key Decisions

Graphical, not decorative

Each concept must teach orientation, relationship, priority, sequence, or final synthesis. Purely decorative skins do not count.

Use existing generated fields first

Question, keywords, confidence, rationale, summary, and learning objective are enough to prototype these visuals before changing generation schemas.

Make energy a mode

High-color manga and hook cards are valuable in review contexts, but calm Cornell reading should remain available.

Keep text real

Question, keyword, and summary text should remain selectable and readable as HTML. SVG and CSS carry layout, relationships, and emphasis.

Scope Boundaries

In scope

  • Directional HTML mockups for five graphical study surfaces.
  • Future UI requirements for question, keyword, and summary display.
  • Ideas that could render as a non-destructive Obsidian layer.

Deferred for planning

  • Exact CodeMirror placement mechanics.
  • Settings taxonomy and default preset choice.
  • Whether richer generated fields are needed after display prototypes.

Out of scope

  • Implementing plugin code in this brainstorm.
  • Replacing the calm Cornell view entirely.
  • Spaced-repetition scheduling or scoring systems.

Assumptions

  • Obsidian CodeMirror can host richer HTML decorations than the current cue widget.
  • The first prototype can use current cache fields and CSS/SVG decorations.
  • Expressive review modes are acceptable as opt-in surfaces.
