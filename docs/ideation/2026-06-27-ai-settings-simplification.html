Design thesis

Make AI setup feel like choosing a tool, not reading a manual.

Implementation handoff

Recommended path: Option A now, Option C later if key editing grows.

Option A keeps the current single-page settings architecture, but removes the instructional scaffolding. It should be the smallest production change with the biggest clarity gain.

Replace the provider dropdown

Use a compact rounded provider button group with icon, name, selected border, and radio dot. Import provider icons from react-icons/si where available.

Collapse copy into labels

Remove numbered headings. Keep short field labels: API key, Command, Model, Test connection, Parallel requests.

Make status local

Move Key saved, Model selected, and Verified chips into the active provider panel instead of a separate setup-status row.

Keep speed secondary

Show the slider as an Advanced row or disclosure. Most users should not have to read it while choosing a provider.

Use provider-specific language

CLI providers say Command and Model override. Cloud providers say API key and Model. Ollama says Host and Local model.

Preserve existing settings primitives

Build with Obsidian CSS variables, CueCraft status chips, and the existing model combobox. Use react-icons/si where available and the supplied OpenRouter SVG.

Likely first PR

Add provider icon metadata and a reusable provider picker component in settings. Use react-icons/si exports where available, plus the supplied OpenRouter SVG.

Likely second PR

Restructure the AI model subpage around the active provider panel, moving existing credential/model/status renderers into the compact layout.

Likely third PR

Move parallel requests into an Advanced row and tighten copy across provider-specific fields.

Optional later PR

Introduce setup modals for editing API keys if inline key editing still makes the page feel too busy.
