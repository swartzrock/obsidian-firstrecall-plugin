Ideation artifact

BYOK should copy the AI SDK's simplicity, not its exact API.

The current BYOK interface is useful but runtime-first. A public open-source library should make first text generation feel like the product, then reveal transport, setup, registry, and provider-specific machinery only when the caller asks for it.

Grounding Context

BYOK today: the README describes a provider runtime library for user-supplied AI accounts. The quick start imports createByokProvider, ByokHttpClient, and ByokProviderDeps, manually constructs an HTTP adapter, constructs dependencies, creates a runtime, tests the connection, then calls provider.generateText. The API reference confirms the core factory requires config plus ByokProviderDeps, and that the runtime exposes testConnection, optional listModels, generateText, and optional generateObject.

AI SDK comparison: Vercel positions AI SDK as a TypeScript toolkit that standardizes provider integration so developers can focus on app work rather than provider details. Its first text example imports generateText from ai and calls it with model and prompt. The dedicated generating-text page names the core surface as two functions, generateText and streamText, while still exposing advanced result details for callers that need them.

Current BYOK first success

import {
  createByokProvider,
  type ByokHttpClient,
  type ByokProviderDeps,
} from "@cuecraft/byok";

const http: ByokHttpClient = async (request) => {
  const response = await fetch(request.url, {
    method: request.method,
    headers: request.headers,
    body: request.body,
  });
  const text = await response.text();
  return {
    status: response.status,
    text,
    json: text ? JSON.parse(text) : null,
  };
};

const provider = createByokProvider(
  { provider: "openai", apiKey, model: "gpt-4o-mini" },
  { fetchImpl: fetch, http }
);

const status = await provider.testConnection();
if (!status.ok) throw new Error(status.message);

const { text } = await provider.generateText({ prompt });

Recommended BYOK first success

import { generateText } from "@cuecraft/byok";

const { text } = await generateText({
  provider: "openai",
  apiKey: process.env.OPENAI_API_KEY!,
  model: "gpt-4o-mini",
  prompt: "Explain RAG in two sentences.",
});
Core distinction: AI SDK can hide credentials behind provider conventions. BYOK should keep credentials explicit, but everything else in the first call should be defaulted or deferred.

Topic Axes

  • First-call ergonomics: what a developer must know before generating text.
  • Public surface boundaries: what belongs in the default import versus advanced subpaths.
  • Transport and runtime escape hatches: where custom fetch, Ollama HTTP, and CLI execution should live.
  • Capability discovery: how callers learn what model listing, structured output, and local execution can do.
  • AI SDK relationship: whether BYOK is a clone, facade, adapter, or complementary credential layer.

Ranked Ideas

  • 1. Ship a function-first facade as the default API
  • 2. Split the public surface into happy-path and advanced subpaths
  • 3. Add a credential-bound client for repeated calls
  • 4. Be AI-SDK-shaped, not AI-SDK-identical
  • 5. Make transport injection optional on the happy path
  • 6. Replace optional-method guessing with explicit capabilities
  • 7. Invert the README around the first useful call
1

1. Ship a function-first facade as the default API

Confidence 92% · Complexity Medium

Description: Make generateText, streamText, and later generateObject the default public verbs. They should accept explicit BYOK credentials and model selection, create the provider runtime internally, use default transports when available, and return a tiny result. The runtime factory remains available, but it is no longer the first concept in the README.

Axis
First-call ergonomics
Basis
direct: BYOK's README currently requires the caller to learn ByokHttpClient, ByokProviderDeps, createByokProvider, testConnection, and generateText before first output. AI SDK demonstrates that a top-level generateText({ model, prompt }) can be the first mental model.
Rationale
This is the biggest simplification because it removes entire concepts from the first success path while preserving them underneath.
Downsides
Needs careful option naming and a migration story so runtime users do not feel demoted.
2

2. Split the public surface into happy-path and advanced subpaths

Confidence 86% · Complexity Medium

Description: Make @cuecraft/byok small: top-level generation functions, createByok, provider IDs, errors, and minimal generation types. Move provider registry UI metadata to @cuecraft/byok/registry, setup-state helpers to @cuecraft/byok/setup, runtime factories and transports to @cuecraft/byok/runtime, Anthropic selection helpers to @cuecraft/byok/anthropic, and CLI providers to @cuecraft/byok/node.

Axis
Public surface boundaries
Basis
direct: The current barrel exports registry helpers, setup-status helpers, portable model helpers, Anthropic model-selection helpers, provider factories, storage/settings types, transport types, runtime types, and errors from one default entrypoint.
Rationale
Open-source API design is partly about what autocomplete teaches. A smaller default export list tells developers the library is easy before they read prose.
Downsides
Subpath exports add package-maintenance work and must be stable once published.

3. Add a credential-bound client for repeated calls

Confidence 84% · Complexity Medium

Description: Add a small createByok client for apps that make multiple calls with the same provider credential. The top-level function handles one-off generation; the client handles repeated generation, model listing, and optional verification without recreating options on every call.

import { createByok } from "@cuecraft/byok";

const ai = createByok({
  provider: "openai",
  apiKey: process.env.OPENAI_API_KEY!,
});

const { text } = await ai.generateText({
  model: "gpt-4o-mini",
  prompt: "Write a changelog note.",
});
Axis
First-call ergonomics
Basis
reasoned: BYOK's differentiator is app-owned credentials. Binding the credential once matches that domain better than repeating apiKey in every call, while still keeping the first one-off call tiny.
Rationale
This gives BYOK its own idiom instead of only shadowing AI SDK.
Downsides
Must avoid becoming just a renamed ByokProviderRuntime; it should be a convenience facade, not another heavy object.

4. Be AI-SDK-shaped, not AI-SDK-identical

Confidence 80% · Complexity Medium/High

Description: Adopt the same ergonomic grammar where it overlaps: function names like generateText and streamText, option-object calls, { text } as the obvious result, and advanced fields behind explicit result access. Do not copy AI SDK's exact model abstraction or full result contract. Instead, optionally expose adapters for callers that already use AI SDK.

Axis
AI SDK relationship
Basis
external: AI SDK's docs present generateText and streamText as the core text interface, while its result object includes a broad set of advanced fields. BYOK currently depends on AI SDK packages internally, but its domain includes explicit user credentials, local providers, and setup state.
Rationale
Exact copying creates false compatibility and permanent version-drift pressure. Shape-level alignment lets BYOK feel familiar while staying honest about its BYOK-specific job.
Downsides
Adapter boundaries need crisp docs: "Use AI SDK directly for full AI SDK semantics; use BYOK when user-owned credentials and local providers are the product."
5

5. Make transport injection optional on the happy path

Confidence 88% · Complexity Low/Medium

Description: Keep custom transports, but default fetchImpl to globalThis.fetch and provide a built-in HTTP adapter for runtimes where fetch exists. Let callers pass transport only when they need Electron IPC, tests, request signing, or a custom Ollama host adapter.

Axis
Transport and runtime escape hatches
Basis
direct: The API reference says ByokProviderDeps requires both fetchImpl and http. The README's improvement notes already identify a Node helper to remove repeated adapter code.
Rationale
This is a high-value cleanup even if no other API changes ship. The required http adapter is the loudest accidental complexity in the quick start.
Downsides
Browser, Electron, Node, and test environments need clear default behavior and clear errors when no fetch exists.
6

6. Replace optional-method guessing with explicit capabilities

Confidence 76% · Complexity Medium

Description: Add a small capability descriptor for provider/runtime features: modelListing, structuredOutput, streaming, localExecution, and requiresNetwork. Keep optional methods internally if convenient, but public callers should not need to infer support by checking whether runtime.generateObject or runtime.listModels exists.

Axis
Capability discovery
Basis
direct: README notes that structured object generation requires checking whether provider.generateObject exists, and the SDK improvement notes call this out as something to make explicit.
Rationale
This reduces provider-specific branching in host apps and makes docs easier: "check capabilities" is simpler than "probe method existence."
Downsides
Must avoid recreating provider-specific metadata bloat. Capabilities should be booleans or enums, not pricing/context/recommendation metadata.
7

7. Invert the README around the first useful call

Confidence 82% · Complexity Low

Description: Rewrite the README so the first screen shows install plus one text-generation snippet. Provider tables, transport customization, connection tests, model discovery, setup state, local CLI providers, and registry metadata move below a "When you need more" section. The first paragraph should say BYOK is the simple way to call AI providers with user-supplied credentials.

Axis
Public surface boundaries
Basis
external/direct: AI SDK leads with a tiny generation example before advanced concepts. BYOK currently leads with feature breadth, provider support, entrypoints, transports, and runtime mechanics before first text.
Rationale
This is the cheapest perception win and a forcing function for whether the API is actually simple enough.
Downsides
Docs-only improvement will not be enough if ByokProviderDeps remains required for first success.

Strong Recommendation

Do not copy the exact AI SDK API. Copy its ergonomic shape: top-level verbs, one options object, tiny examples, advanced power below the fold. BYOK has a different center of gravity: explicit user-owned credentials, provider setup, model discovery for settings UIs, local providers, and host-controlled transports. If BYOK copies AI SDK exactly, it becomes either a confusing clone or a wrapper that must track AI SDK semantics forever.

The strongest product API is a layered facade:

// 1. One-off happy path
const { text } = await generateText({
  provider: "openai",
  apiKey,
  model: "gpt-4o-mini",
  prompt,
});

// 2. Repeated-call client
const ai = createByok({ provider: "openai", apiKey });
const { text } = await ai.generateText({ model: "gpt-4o-mini", prompt });

// 3. Advanced runtime escape hatch
const runtime = createByokRuntime(config, { transport, appInfo });

The public README should teach layer 1 first, layer 2 second, and layer 3 only when the caller needs custom transport, connection testing, model listing, or local execution.

Rejection Summary

#IdeaReason Rejected
1Copy AI SDK's exact API and result contractFalse parity. BYOK cannot honestly mirror every AI SDK behavior without becoming a drift-prone wrapper.
2Use one magic model string for everythingTempting, but OpenRouter slash IDs, Ollama colon tags, and local CLI semantics make a single string too magical as the only API.
3Only add createByokNodeDeps()Useful but too small. It removes adapter boilerplate but leaves the runtime-first mental model intact.
4Move all provider registry metadata into the default docsWorsens the problem. Registry metadata is for settings UIs, not the first generation call.
5Remove listModels from the libraryOver-corrects. BYOK settings flows need model discovery; it should move down a layer, not disappear.
6Require testConnection before every documented generationConnection testing is valuable for setup flows, but making it mandatory in the happy path adds ceremony before value.
7Expose provider-specific model metadata in portable model optionsAlready correctly removed. Pricing, context length, and badges are uneven across providers and belong in provider-specific APIs or apps.
8Make local CLI providers part of the main first-call exampleCLI execution is important but changes the trust and runtime model. Keep it in @cuecraft/byok/node.
