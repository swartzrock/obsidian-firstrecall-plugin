What the ideas had to survive

Grounding Context

Browser reality

The shipped plugin is desktop-only: its production bundle targets Node/CommonJS and externalizes Obsidian, Electron, and CodeMirror. The browser path is an honest host adapter—not the unchanged plugin bundle.

Reusable CueCraft core

Parsing, schemas, cache types, Cornell model construction, interaction state, and exported DOM renderers already provide browser-safe seams. Provider generation is injected behind a typed CueCraft runtime.

Hidden cost multiplier

A full note may trigger one call per section, Summary, Note Brief, schema repair, rate-limit retries, and five-way concurrency. The safe public unit is a bounded artifact—not “generate this note.”

Model specialization

CueCraft already owns the pedagogical prompt, source boundary, schemas, validation, and repair. Groq does not train models, and LoRA inference is enterprise-only, so free-plan specialization means a qualified base model plus CueCraft’s contract.

Identity is a product choice

Turnstile proves an admission event. A signed cookie and IP/subnet approximate a browser session. Only authentication supplies a durable “person” to which an exact allowance can be attached.

Limiters have different jobs

Worker Rate Limiting is fast, location-local, and eventually consistent. A Durable Object can serialize exact session credits and concurrency. A dedicated Groq project quota is the final blast-radius boundary.

Current provider envelope. On 2026-08-15, relevant Groq free-plan models were documented at 30 RPM, 1,000 RPD, 8,000 TPM, and 200,000 TPD at the organization level. Treat the account’s live Limits page as authoritative and keep the demo’s project cap below it. See Groq rate limits, projects and quotas, and LoRA availability.

Cloudflare facts used in the cut. See the official docs for Worker Rate Limiting, Turnstile validation, Durable Object sharding, and AI Gateway BYOK.

1. Strict anonymous live lane

Top pickConfidence · 93%Complexity · High

Put a Cloudflare Worker in front of a narrow CueCraft operation. After Turnstile admission, mint a signed anonymous session; a session-sharded Durable Object atomically reserves the bounded operation allowance, enforces one in-flight request and idempotency, then the Worker calls a fixed Groq model using a secret. A small global guardian leases bounded reserve blocks rather than proxying every stream, while a dedicated Groq project quota caps the final blast radius.

Axis
Quota ledger and deployment topology
Basis
direct: CueCraft can multiply one note action through sections, repairs, and retries, and has no shared requester ledger. external: Worker Rate Limiting is approximate; Durable Objects serialize exact session state; Groq project quotas provide a provider-level cap.
Rationale
This is the strongest anonymous design because it accounts in CueCraft operations rather than HTTP requests. Hiding the key is necessary but insufficient; admission, exact session spend, global reserve, and provider cap each constrain a different abuse path.
Downsides
Highest initial complexity. Reservation/refund semantics, global lease sizing, and failure recovery need careful definition; a global object must not sit on every request path.

2. CueCraft Web Host with one live aperture

Confidence · 95%Complexity · Medium

Build an Obsidian-faithful browser host around CueCraft’s real browser-safe parser, Cornell model, cache logic, interaction state, and DOM renderers. Pre-generate the realistic vault and permit exactly one highlighted live operation—preferably regenerate one selected section—so the visitor sees source text become an active-recall cue without exposing full-note fan-out. Document which layers are shared CueCraft code and which are showcase adapters.

Axis
Browser showcase authenticity
Basis
direct: manifest.json marks the plugin desktop-only and esbuild.config.mjs targets Node/CommonJS, while src/cornell.ts is explicitly pure and renderer tests already run against browser DOM.
Rationale
This preserves the product’s real learning behavior without spending effort on brittle desktop emulation. Limiting live scope to one section also turns the user-visible interaction into a predictable security and cost unit.
Downsides
The host must track shared core changes and can drift visually from Obsidian. The page must be candid that it is a web host for CueCraft rather than the Obsidian desktop runtime.

3. CueCraft generation profile and model bake-off

Confidence · 94%Complexity · Medium

Treat CueCraft’s protected prompt, examples, schemas, validation, and repair policy as the note-taking specialization. Run a small repeatable bake-off across current Groq base models using realistic lecture, meeting, research, and technical notes; score source faithfulness, active-recall usefulness, schema success without repair, prompt-injection resistance, latency, and token use, then pin the winner server-side.

Axis
LLM contract and model fit
Basis
direct: CueCraft already instructs models to create grounded active-recall questions and retains artifact count, JSON shape, source boundaries, validation, and repair. external: Groq LoRA is enterprise-only and Groq does not provide training.
Rationale
The valuable specialization is the pedagogical contract CueCraft can own and test, not a model label. Repair rate also feeds the quota envelope: a model that often violates schemas is more expensive even when its first-token latency looks good.
Downsides
Requires a curated evaluation corpus and judgment rubric. Model availability and behavior change, so the winner must be requalified rather than treated as permanent.

4. Worker-only MVP with a hard provider backstop

Confidence · 84%Complexity · Low

Start with one Worker holding the Groq secret and accepting only a narrow, fixed-model CueCraft operation. Add Turnstile-minted sessions, coarse session/IP burst limits, strict input/output caps, cache keys, a conservative application stop, and a dedicated Groq project quota. Explicitly describe anonymous limits as approximate and do not display exact remaining credits.

Axis
Quota ledger and deployment topology
Basis
external: Groq requires a trusted backend and Worker secrets satisfy key custody; Worker Rate Limiting supports cheap burst suppression; Groq project quotas bound provider exposure. reasoned: one anonymous live artifact can tolerate soft per-session fairness if the hard project blast radius is small.
Rationale
This is the smallest architecture that safely hides the key and makes the endpoint useless as a generic proxy. It is a sensible low-traffic proof before exact ledgers have earned their complexity.
Downsides
Not exact: cookie clearing, distributed IPs, multi-region races, and simultaneous duplicate requests can exceed application soft limits until the provider cap stops them. If accurate credits or one-in-flight guarantees matter, graduate to idea 1.

5. Truthful identity ladder

Confidence · 91%Complexity · Medium

Give a Turnstile-approved anonymous browser one small session allowance and call it exactly that. If the showcase later needs durable repeat usage, require a lightweight authenticated identity for the larger allowance and key exact credits by account ID. Use IP/subnet only as a secondary abuse signal, never as the definition of a person.

Axis
Visitor identity and abuse resistance
Basis
external: Turnstile tokens are single-use, short-lived admission proofs; shared IPs, cookies, and browser storage do not establish durable human identity.
Rationale
This avoids both false security claims and premature signup friction. Identity becomes a progressive product tradeoff: anonymous proof of value first, authenticated continuity only when additional quota justifies it.
Downsides
Anonymous users can evade a session allowance by clearing state or changing networks. Authentication adds conversion friction, account operations, and privacy considerations.

6. Zero-spend launch, graceful brownout always

Confidence · 90%Complexity · Low

Launch with scheduled, validated real-LLM output and no visitor-triggered provider calls; publish the generation time, model, and profile version. Once the browser experience proves compelling, open one live aperture. At every stage, keep the full pre-generated vault usable and label each result as live, shared/cached, or replayed when the daily reserve is closed.

Axis
Live generation scope
Basis
direct: CueCraft’s Cornell and Study Mode interactions work locally, and provider failures are already isolated rather than crashing the note. reasoned: scheduled real output proves integration while creating zero public spend risk, and the same known-good artifacts form the brownout path later.
Rationale
This is the safest rollout and makes provider exhaustion a designed product state rather than an outage. The showcase remains persuasive even during launch spikes, attacks, or Groq 429s.
Downsides
The initial version is not visitor-interactive LLM generation, so provenance must be conspicuous enough to distinguish it from a static mock. Brownout copy and cache-version equivalence require care.

7. Operations-rich AI Gateway layer

Confidence · 79%Complexity · Medium

Route the Worker’s validated Groq call through Cloudflare AI Gateway to add Groq BYOK, logs, exact-request caching, analytics, routing, and budget/count rules. Keep the browser outside both credentials, and keep session credits, idempotency, and request locks in the Worker/Durable Object path; Gateway is an operations layer, not the correctness boundary.

Axis
Quota ledger and deployment topology
Basis
external: AI Gateway BYOK, caching, and routing/budget features are directly applicable, but authentication stays server-side and simultaneous duplicate requests can still reach the provider.
Rationale
It adds useful visibility and an additional budget layer without changing the public protocol. It is especially valuable once model qualification, latency, cache hits, and failure rates need real operational evidence.
Downsides
Additional platform configuration and another token/credential surface. It can tempt the design to duplicate controls or mistake observability/cache behavior for exact admission accounting.
