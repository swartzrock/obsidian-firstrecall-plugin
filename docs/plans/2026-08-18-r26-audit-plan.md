# CueCraft R26 Vocabulary Audit and Remediation Plan

## Objective

Finalize the R26 vocabulary alignment introduced by
`docs/ideation/2026-08-17-cuecraft-vocabulary-review.html` by removing the remaining
user-facing legacy terms and stabilizing copy/tests/docs so the product and tests expose one
approved surface language.

## Audit scope

- Surfaces: commands, notices, settings UI text, visibility/accessibility copy, README, glossary, and
  tests that assert user-facing strings.
- Exclusions: internal type/model names (`StudyArea`, CSS selectors like `:scope`, internal error codes),
  and the old deck (`docs/ideation/2026-08-17-cuecraft-vocabulary-review.html`) itself, which is the
  authority source.
- Date reference: 2026-08-18

## Remediation plan

### Phase 1 — User-facing runtime copy and command names (implementation unit)

1. Rename command label:
   - `src/main.ts` → `Manage folders & automatic updates` to approved managed-coverage naming (keeping existing command id `manage-study-areas` and test selectors stable).
2. Update runtime notices using scope wording in:
   - `src/main.ts` (duplicate scope/conflict and no-work messages)
   - `src/settings.ts` (summary text, headings, notices, suggestions, scan/disabled-state copy)
3. Update managed-folder note-brief preview copy:
   - Replace old card names with an R26-aligned wording that does not mention `Core idea`, `Review first`, `Self-test`.
4. Update corresponding tests:
   - `tests/study-plugin-integration.test.ts:351`
   - `tests/settings.test.ts:688-690` (and any related snapshots/assertions)
5. Verification for this phase:
   - No stale user-facing string assertions on old R26 terms.
   - Quick grep pass for exact legacy phrases in command/notice strings listed above.
   - Re-run `bun test` for edited specs.

### Phase 2 — Docs/contracts cleanup

1. Update glossary and user docs:
   - `docs/CueCraft-Glossary.md` coverage section to use R26 managed-folder terms.
   - `README.md` Managed folders section to remove legacy “scope” language and use approved wording.
2. Add/refresh acceptance wording in plan notes so R26 remains an explicit audit gate for docs and code.
3. Verification:
   - Human scan of README + glossary for consistency.
   - Add a terminology checklist line to ensure no regression against R26 scope terms in docs.

### Phase 3 — Global alignment sweep

1. Expand scan across user-facing surface files (`src`, `docs`, and tests) for the remaining explicit legacy tokens:
   - `Scope`/`scope` when rendered to users,
   - `Core idea`, `Review first`, `Self-test`,
   - `automatic-update scope`.
2. Resolve only user-facing mismatches; preserve internal technical names and test internals where needed for correctness.
3. Update any failing snapshots and assertions after wording changes.
4. Verification:
   - `bun run lint`
   - `bun test`
   - targeted manual smoke in Obsidian for Settings → “Managed folders” and command palette entry.

## Acceptance criteria

- R26 surfaces expose a single vocabulary set (No new user-facing “scope”/“automatic-update scope”/`Core idea`/`Review first`/`Self-test` copy outside planned internal boundaries).
- Command assertions, settings assertions, and user documentation agree on the approved phrasing.
- Existing behavior/feature flags remain unchanged; this is terminology-only.
- Existing automation/coverage semantics from prior folder-management change remain intact.
