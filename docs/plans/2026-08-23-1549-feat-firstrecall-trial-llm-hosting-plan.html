FirstRecall Trial LLM Hosting - Plan

A low-cost path to make FirstRecall useful on first launch: give new installations a small, selected-by-default Qwen trial without operating a model-serving stack or exposing a master API credential.

Recommendation Mint short-lived, model-restricted DeepInfra scoped JWTs from a tiny serverless issuer. Let the plugin call Qwen3.5-9B directly, cap each token at roughly half a cent, and cap the whole account at $8 per month with no automatic top-up.

Goal Capsule

Goal Capsule

Objective

New FirstRecall users can generate real study material immediately, while the operator can serve many small trials without spending $10 or more in a month.

Product authority

This plan owns the default trial provider, its user-visible lifecycle, its cost ceiling, and abuse posture.

Open blockers

Provider cap enforcement and model output quality must pass a bounded pre-launch spike.

Product Contract

Product Contract

Summary

FirstRecall will add a distinct trial provider that is enabled and selected for fresh installations. A lightweight issuer will grant a tiny, expiring credential for one Qwen model; inference will travel directly from the plugin to the model host.

Problem Frame

FirstRecall currently opens with no provider selected. Before users can see a Note Brief or section study cards, they must choose a provider, obtain a credential, choose a model, save the key, and test the connection. That setup wall appears before the product proves its value.

The operating budget rules out a conventional hosted GPU. It also rules out an unlimited anonymous proxy: a public desktop plugin can be inspected and automated, and any static secret embedded in it is public in practice. The useful constraint is therefore not “prevent all abuse,” which is impossible without stronger identity, but “make every stolen trial tiny, make mass issuance expensive, and make the global loss finite.”

Key Decisions

Host credential issuance, not inference.

The service remains small and note content bypasses FirstRecall-operated infrastructure. Governs R3, R8, R9, R13.

(session-settled: user-approved — chosen over a task-specific inference gateway and self-hosted GPU: it removes the model-serving and request-proxy stack while keeping provider-enforced limits.)

Use DeepInfra scoped JWTs as the launch path.

DeepInfra exposes model, expiry, and spend restrictions intended for third-party access. Governs R7, R8, R10.

(session-settled: user-approved — chosen over OpenRouter micro-keys: it provides the needed delegation controls with fewer routing and privacy layers.)

Keep activation anonymous at launch.

A browser challenge and risk limits protect issuance without requiring an account. Governs R4, R11, R12.

(session-settled: user-approved — chosen over mandatory GitHub or email sign-in: first-use friction matters more than perfect person-level uniqueness for a half-cent trial.)

Start the quality gate with Qwen3.5-9B in non-thinking mode.

The current model is inexpensive, supports JSON output, and reports strong instruction-following results. Governs R14, R15.

(session-settled: user-approved — chosen over larger Qwen models as the initial candidate: the trial needs representative study cards, not frontier reasoning.)

Budget model

What “many users under $10” can mean

$0.10 / MQwen3.5-9B input tokens
$0.15 / MQwen3.5-9B output tokens
$8recommended monthly inference hard cap
≈ 1,600+half-cent installation trials per $8

The current plugin limits note text injected into a prompt to 8,000 characters. A representative eight-section note is estimated at roughly 22,000 input tokens and 1,300 output tokens across section cards and the Note Brief. At current Qwen3.5-9B pricing, that is about $0.0024 before retries. A $0.005 lifetime token should therefore cover at least one representative note while keeping stolen-token value negligible.

Interpretation: the system can support many installations, not unlimited simultaneous entitlement. Once the monthly cap is reached, trial issuance and inference fail closed until reset; BYOK providers remain available.

Actors

Product Requirements

Product Requirements

Default experience and lifecycle

  1. R1.A fresh installation presents a distinct FirstRecall Trial provider as enabled and selected by default.
  2. R2.Existing installations preserve their saved provider selection and credentials during upgrade.
  3. R3.A new user can start the trial without supplying an API key or choosing a model.
  4. R4.The first generation may require a one-time browser anti-bot claim, but not account creation.
  5. R5.The trial communicates remaining availability in human terms and directs exhausted users to existing BYOK providers.
  6. R6.Trial exhaustion never silently switches a user's note to another funded model or another user's credential.

Cost and delegated access

  1. R7.The combined trial infrastructure hard-stops below $10 per calendar month, with an $8 default inference cap and no automatic top-up.
  2. R8.Each installation receives only an expiring credential restricted to the selected trial model and a lifetime micro-budget.
  3. R9.The plugin never contains, downloads, or persists the master provider credential.
  4. R10.The provider account enforces a second global spending limit independent of FirstRecall's issuer state.

Abuse resistance and privacy

  1. R11.Trial issuance validates a single-use browser challenge and rejects abnormal claim velocity by installation and network risk signals.
  2. R12.The issuer records only the minimum pseudonymous data needed to prevent repeated claims and expires that data on a documented schedule.
  3. R13.Note content travels directly from Obsidian to the inference provider and is never sent to the FirstRecall token issuer.
  4. R14.Before first generation, FirstRecall discloses that the selected trial sends relevant note content to DeepInfra and links its current data-handling policy.
  5. R15.The operator can stop new issuance immediately and existing trial credentials expire without a plugin release.

Model quality and compatibility

  1. R16.The launch model passes the existing section-card and Note Brief JSON contracts on a representative note corpus before becoming the default.
  2. R17.The trial disables model thinking and caps completion length so hidden reasoning cannot consume the allowance.
  3. R18.Existing Anthropic, OpenAI, DeepInfra, OpenRouter, local, and CLI provider choices remain available without trial coupling.

Security posture: an anonymous desktop trial cannot prove “one human, one trial.” The launch bar is economic containment: the work needed to obtain enough half-cent credentials should cost materially more than the inference they unlock, and a failure must never exceed the global cap.

Key Flows

F1.

Trigger: A fresh installation opens FirstRecall or requests its first generation.

Flow: The trial is already selected. FirstRecall opens a browser claim, receives the scoped credential, stores it through Obsidian Secret Storage, and starts generation.

Covers R1, R3, R4, R8, R9, R11.

F2.

Trigger: The user generates study material while trial capacity remains.

Flow: FirstRecall sends the bounded prompt directly to DeepInfra with thinking disabled, validates the JSON result, and uses the existing single repair path when needed.

Covers R13, R16, R17.

F3.

Trigger: The installation allowance, credential expiry, or monthly pool is exhausted.

Flow: FirstRecall explains that the trial has ended and offers the existing provider picker; saved study material remains usable.

Covers R5, R6, R7, R10, R18.

F4.

Trigger: Abuse or cost signals exceed the operator's tolerance.

Flow: The operator disables issuance or lowers the provider cap without releasing a new plugin; issued credentials age out.

Covers R10, R15.

Acceptance Examples

AE1.

Covers R1-R4. Given a fresh installation with no settings, when the user asks for study material, the FirstRecall Trial is already selected and the only setup interruption is the one-time browser claim.

AE2.

Covers R2, R18. Given an upgrade with OpenAI selected, when the new plugin loads, OpenAI remains selected and no trial credential is requested.

AE3.

Covers R5-R7. Given an exhausted installation or global allowance, when generation is requested, no paid inference begins and the user sees how to choose a BYOK provider.

AE4.

Covers R8-R10. Given a copied trial JWT, when it is used after expiry, for another model, or beyond its spend cap, DeepInfra rejects it without exposing the master credential.

AE5.

Covers R11, R12. Given automated repeated claims from one installation or network range, when the configured velocity is exceeded, the issuer denies additional credentials without consuming inference budget.

AE6.

Covers R13, R14. Given a user has not yet accepted the trial disclosure, when they begin activation, note content is not transmitted until the disclosure is shown and accepted.

AE7.

Covers R16, R17. Given the launch evaluation corpus, when Qwen3.5-9B runs with thinking disabled, section-card and Note Brief outputs pass existing schemas at the agreed quality threshold and within the trial cost envelope.

Success Criteria

  • A new user can produce a Note Brief and section study cards without bringing an API key.
  • Measured paid trial infrastructure remains below $10 in every calendar month, including abuse events.
  • At least 95% of the launch evaluation corpus produces schema-valid output within the existing initial-plus-repair allowance.
  • No plugin package, settings file, renderer surface, or network response exposes a master inference credential.
  • Disabling the trial never disables or alters user-funded providers.

Dependencies / Assumptions

  • DeepInfra continues to support scoped JWTs restricted by model, expiry, and dollar spend.
  • DeepInfra's account-level spending limit is configured independently from FirstRecall's issuer.
  • A free serverless tier can host the claim and issuance path within its request limits.
  • Obsidian Secret Storage remains the trusted location for the issued trial credential.
  • The user accepts that a strict global budget can make the trial temporarily unavailable during a popular release.
  • DeepInfra currently states that ordinary inference input and output are held in memory and not used for training, subject to its documented security-debugging exception.

Outstanding Questions
